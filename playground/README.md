# jrsonnet Playground

A browser-based Jsonnet editor and evaluator powered by jrsonnet compiled to WebAssembly.

## Prerequisites

- **Rust** with the `wasm32-unknown-unknown` target:
  ```bash
  rustup target add wasm32-unknown-unknown
  ```
- **wasm-pack** (v0.13+):
  ```bash
  cargo install wasm-pack
  ```
- A local HTTP server (WASM modules cannot be loaded from `file://` URLs).
  Python 3 works out of the box, or use any static file server.

## Quick Start

From the repository root (`jrsonnet/`):

```bash
# 1. Build the WASM package
wasm-pack build crates/jrsonnet-wasm --target web

# 2. Start a local server
python3 -m http.server 8080

# 3. Open the playground
open http://localhost:8080/playground/index.html
```

The first build takes ~30s. Subsequent rebuilds are incremental (~5s).

## How It Works

1. `index.html` loads CodeMirror 6 from CDN via ES module import maps.
2. On page load, the WASM module is fetched and instantiated.
3. A `Jrsonnet` instance is created — this initializes the full Jsonnet standard library in WASM memory.
4. When you press **Ctrl+Enter** (or **Cmd+Enter** on macOS), the editor contents are passed to `vm.evaluate_snippet()`, which parses and evaluates the Jsonnet, then manifests the result as JSON.

## JavaScript API

The WASM module exposes a `Jrsonnet` class:

```js
import init, { Jrsonnet, version } from "./crates/jrsonnet-wasm/pkg/jrsonnet_wasm.js";

// Initialize the WASM module (must be called first)
await init();

// Create a VM instance
const vm = new Jrsonnet();

// Basic evaluation
const json = vm.evaluate_snippet("main.jsonnet", '{ a: 1 + 1 }');
// => '{\n    "a": 2\n}'

// Register virtual files for imports
vm.add_file("lib.libsonnet", '{ greet(name):: "Hello, " + name }');
const result = vm.evaluate_snippet("main.jsonnet", `
  local lib = import "lib.libsonnet";
  lib.greet("world")
`);
// => '"Hello, world"'

// Dynamic import resolution via callback
vm.set_import_callback((path) => {
  // Return file contents as string, or null if not found
  if (path === "config.json") return '{"key": "value"}';
  return null;
});

// External variables
vm.ext_var("env", "production");
vm.evaluate_snippet("main.jsonnet", 'std.extVar("env")');
// => '"production"'

// External code variables
vm.ext_code("config", '{ replicas: 3 }');
vm.evaluate_snippet("main.jsonnet", 'std.extVar("config").replicas');
// => '3'

// Cleanup
vm.remove_file("lib.libsonnet");
vm.clear_import_callback();
vm.free(); // Release WASM memory
```

## Async Import Resolution (fetch)

The `evaluate_snippet` method is synchronous, but you can implement async imports
by pre-fetching files before evaluation:

```js
async function evaluateWithRemoteImports(vm, code) {
  // Find import paths in the code (simple regex approach)
  const importRegex = /import\s+["']([^"']+)["']/g;
  let match;
  while ((match = importRegex.exec(code)) !== null) {
    const path = match[1];
    if (path.startsWith("http://") || path.startsWith("https://")) {
      const response = await fetch(path);
      const contents = await response.text();
      vm.add_file(path, contents);
    }
  }

  return vm.evaluate_snippet("main.jsonnet", code);
}
```

## Troubleshooting

**WASM fails to load with MIME type error**
Your HTTP server must serve `.wasm` files with `application/wasm` MIME type.
Python's `http.server` does this correctly. If using nginx/apache, add:
```
# nginx
types { application/wasm wasm; }

# apache
AddType application/wasm .wasm
```

**"SharedArrayBuffer is not defined" or CORS errors**
Some browsers require specific headers for WASM. If you encounter this,
start your server with CORS headers:
```bash
# Using npx
npx serve -p 8080 --cors

# Or with Python + a simple script
python3 -c "
from http.server import HTTPServer, SimpleHTTPRequestHandler
class Handler(SimpleHTTPRequestHandler):
    def end_headers(self):
        self.send_header('Cross-Origin-Opener-Policy', 'same-origin')
        self.send_header('Cross-Origin-Embedder-Policy', 'require-corp')
        super().end_headers()
HTTPServer(('', 8080), Handler).serve_forever()
"
```

**Build fails with "tree-sitter" error**
Ensure the workspace `Cargo.toml` has `default-features = false` for
`jrsonnet-evaluator`. The `explaining-traces` feature pulls in `hi-doc` which
depends on `tree-sitter` (a C library that cannot compile to wasm32).

**Build fails with "Span size assertion"**
The `static_assertions::assert_eq_size!(Span, (usize, usize))` in
`jrsonnet-parser/src/expr.rs` must be gated with `#[cfg(target_pointer_width = "64")]`
because `Span` is 12 bytes on wasm32 (4+4+4) vs 16 bytes on 64-bit (8+4+4).
